# Кредитный процесс банка «Стандарт»

## Участники и системы

- **Клиент** подаёт заявку только в отделении.
- **Менеджер фронт-офиса** регистрирует заявку в АБС.
- **АБС** (Oracle, бизнес-логика на PL/SQL) хранит заявку, данные клиента и платежи по кредиту.
- **Кредитный конвейер** (Camunda / Oracle) используется менеджерами кредитования для рассмотрения заявки. В нём также хранится связь номеров платежей с кредитным договором.
- **Система кредитного скоринга** (Python / Flask / PostgreSQL) рассчитывает оценку и вызывается конвейером по REST API.
- **Бюро кредитных историй (БКИ)** - внешняя система с REST API, источник кредитной истории.
- **Менеджер отдела кредитования** изучает заявку и принимает решение с учётом параметров заявки и оценки скоринга.

## Последовательность процесса

1. Клиент обращается в отделение. Менеджер фронт-офиса оформляет заявку в АБС и сообщает, что банк рассмотрит её.
2. Раз в сутки заявки из АБС передаются в кредитный конвейер через интеграцию на уровне баз данных. На этом этапе заявка не обрабатывается в онлайн-режиме.
3. Менеджер кредитования рассматривает заявку в кредитном конвейере. Конвейер вызывает сервис скоринга по REST API.
4. Скоринговый сервис использует данные клиента и сведения о платежах, загруженные из БД других систем раз в сутки. История платежей хранится в АБС; связь номеров платежей с кредитным договором - в кредитном конвейере. За актуальной кредитной историей клиента скоринговый сервис обращается в БКИ онлайн во время расчёта.
5. Сервис возвращает оценку в кредитный конвейер. Менеджер кредитования сопоставляет её с параметрами заявки и принимает решение о выдаче кредита.
6. Если кредит одобрен, заявка получает финальный статус в конвейере. Раз в сутки статус передаётся обратно в АБС, где выполняются операции по зачислению кредитных средств на счёт клиента.

## Информационные потоки

| Откуда | Куда | Данные | Режим |
|---|---|---|---|
| Менеджер отделения | АБС | Кредитная заявка | При оформлении в отделении |
| АБС | Кредитный конвейер | Заявки | Пакетно, раз в сутки; интеграция по БД |
| Кредитный конвейер | Система скоринга | Данные заявки для оценки | REST API, при рассмотрении заявки |
| АБС и кредитный конвейер | Система скоринга | Клиентские данные, внутренняя история платежей | Передача данных из БД раз в сутки |
| Система скоринга | БКИ | Запрос кредитной истории | REST API, онлайн во время скоринга |
| БКИ | Система скоринга | Кредитная история | REST API, в ответ на запрос |
| Система скоринга | Кредитный конвейер | Результат скоринга | REST API, в ответ на запрос |
| Кредитный конвейер | АБС | Финальный одобренный статус | Пакетно, раз в сутки |
| АБС | Счёт клиента | Зачисление кредитных средств | После получения одобренного статуса |

## Ограничения текущего процесса

- Подать заявку можно только в отделении; сайт и интернет-банк кредитные заявки не принимают.
- Суточная задержка при передаче заявки и финального статуса не позволяет обещать решение в течение одного дня при любом времени подачи.
- Скоринг зависит от суточной загрузки внутренних данных, тогда как данные БКИ запрашиваются онлайн. Поэтому внешняя кредитная история может быть актуальнее внутренней истории платежей.
- Прямой обмен на уровне баз данных связывает приложения и усложняет развитие интеграций; на схеме отдельно показан REST-вызов скоринга и онлайн-вызов БКИ.
- Данные кредитной заявки распределены между АБС и кредитным конвейером: история платежей находится в АБС, а привязка номеров платежей к договору - в конвейере.
